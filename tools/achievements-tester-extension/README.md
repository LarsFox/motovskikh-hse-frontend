# Расширение для тестирования ачивок

Это отдельный тестовый адаптер для проверки интерфейса и API ачивок на текущей
версии `motovskikh.ru`. Расширение не входит в рабочую клиентскую часть сайта.

В репозитории находится только обычная сборка для тестировщиков. Персональный режим
реального автопрохождения, перехват Raphael и MapLibre, а также диагностический режим
в этот модуль не включены.

## Возможности

- показывает список полученных и неполученных ачивок;
- отображает очередь уведомлений о новых ачивках;
- следует русскому или английскому языку страницы сайта;
- наблюдает результаты одиночных тестов и онлайн-комнат с картами;
- позволяет очистить ачивки выбранного тестового логина;
- эмулирует результат 100% для тестового backend, не подменяя результат рабочего сайта.

## Сборка

Из корня frontend-репозитория выполните:

```powershell
.\tools\achievements-tester-extension\package.ps1
```

Команда создаст игнорируемые Git файлы:

- `tools/achievements-tester-extension/dist/motovskikh-achievements-extension/`;
- `tools/achievements-tester-extension/dist/motovskikh-achievements-extension.zip`.

Общий интерфейс, стили и резервная звёздочка копируются из `src`, поэтому расширение
собирается с той же версией интерфейса, что и сайт.

## Проверка

Для запуска тестов нужен установленный Node.js, но установка npm-пакетов не требуется:

```powershell
.\tools\achievements-tester-extension\run-tests.ps1
```

## Установка

1. Распакуйте ZIP-архив.
2. Откройте `chrome://extensions` или `edge://extensions`.
3. Включите режим разработчика.
4. Нажмите **Загрузить распакованное расширение**.
5. Выберите папку `motovskikh-achievements-extension`.
6. Откройте настройки расширения.
7. Введите адрес тестового backend и выданный тестовый логин.
8. Сохраните настройки и обновите вкладку `motovskikh.ru`.

Адрес тестового backend намеренно не зафиксирован в исходниках. Его передаёт
координатор тестирования.

## Ограничения безопасности

Расширение использует наивную тестовую идентификацию по логину и отдельные маршруты
очистки и эмуляции результата. Эти механизмы нельзя переносить в рабочий контур.
Рабочий сайт должен использовать штатную авторизацию, серверную проверку результата
и выдачу ачивок из ответа существующего запроса `/tests/submit/`.
